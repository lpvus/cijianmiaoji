# 单词抖音搜索设计

## 目标

在网站所有会展示英文单词的学习入口中提供“抖音搜索”按钮。用户点击后，手机、平板和电脑均优先尝试唤起抖音客户端并搜索当前英文单词；无法唤起时自动回退抖音网页版。

## 搜索范围

按钮覆盖以下位置：

- 沉浸学习的当前单词详情。
- 记忆卡片正面显示的单词。
- 遮罩记忆中已显示的单词。
- 记忆测试中已经显示的英文题目，以及提交答案后的结果。
- 收藏夹中的单词。
- 妙计列表中的单词。

当测试题只显示中文释义、要求用户填写英文时，不提前提供搜索按钮，避免泄露答案；英文答案显示后再提供入口。

## 搜索关键词

搜索词严格使用当前英文单词本身，不附加“英语”“单词记忆”或其他文本。生成链接前对单词执行字符串转换、去除首尾空白和 URL 编码；空字符串不执行跳转。

## 跳转策略

### 所有设备

1. 用户主动点击按钮后，首先导航到：

   `snssdk1128://search?keyword=<编码后的英文单词>`

2. 注册约 1.5 秒的网页回退计时器。
3. 如果页面进入后台，视为抖音 App 已被唤起并取消回退。
4. 如果页面仍可见，导航到：

   `https://www.douyin.com/search/<编码后的英文单词>`

抖音 App Scheme 不是面向普通网站公开保证长期兼容的稳定接口，因此网页版回退为必需行为。

电脑端也执行相同的客户端优先策略。抖音提供 Windows 和 macOS 客户端，但没有公开保证桌面客户端一定注册或支持该搜索 Scheme；因此桌面浏览器同样使用页面可见性检测和网页版回退。浏览器可能在首次唤起时显示外部应用确认提示，这是正常的安全行为。

## 代码结构

新增独立模块 `js/douyin-search.mjs`，职责如下：

- 规范化搜索词。
- 生成 App Scheme 和网页版 URL。
- 管理页面可见性和回退计时器。

`js/app.js` 只负责在各学习视图渲染带 `data-douyin-word` 属性的按钮，并通过统一的事件委托调用搜索模块。动态生成的列表无需为每个按钮单独注册监听器。

## 界面

- 大型单词详情和记忆卡片使用可见文字按钮“🎵 抖音搜索”。
- 列表、结果和紧凑区域使用小号“🎵”按钮，`title` 和无障碍标签写明“在抖音搜索 <单词>”。
- 按钮沿用现有 `speak-btn` / `btn ghost sm` 视觉体系，不引入新的品牌图片或远程资源。

## PWA 更新

- 把 `js/douyin-search.mjs` 加入 Service Worker 预缓存资源。
- 提升 `app.js`、新模块引用和缓存版本，确保已经安装 PWA 的用户获取新代码。
- 离线时按钮仍可显示；点击后由浏览器或系统处理外部链接，网络不可用时不修改本地学习数据。

## 安全与隐私

- 只把用户当前点击的英文单词发送给抖音，不发送账号、邮箱、学习进度、妙计或 Supabase 数据。
- 所有搜索词均进行 URL 编码和 HTML 属性转义。
- 跳转必须由用户点击触发，不在页面加载或切换单词时自动打开外部应用。
- 网页回退不向抖音传递原网站窗口控制能力。

## 验证

- 单元测试验证空白清理、特殊字符编码、App URL、网页 URL、移动端回退和页面隐藏时取消回退。
- 静态合约确认六类学习入口均接入统一按钮行为，新模块已被加载并加入 PWA 预缓存。
- 运行现有全部合约测试和 JavaScript 语法检查。
- 本地浏览器逐一检查六类入口，确认不会在中文译英题目作答前泄露答案。
- 部署 Cloudflare 后检查首页、Service Worker 和新模块均返回 HTTP 200，并核对线上链接包含正确编码的单词。
- 将完成的提交推送到 `https://github.com/lpvus/cijianmiaoji`。

## 不在本次范围

- 不调用抖音内容 API，不抓取或嵌入搜索结果。
- 不记录用户点击历史，不新增 Supabase 表或字段。
- 不修改登录、云同步、共享妙计、词库和学习进度算法。
