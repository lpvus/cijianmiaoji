# 词间妙记 Cloudflare 与 Supabase 迁移实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将词间妙记完整迁移到用户自己的 Supabase 与 Cloudflare Pages，同时保持本地、离线和全部学习功能可用。

**Architecture:** 保持项目现有的无构建静态 PWA 架构。新增一份可重复执行的 Supabase 数据库初始化脚本，以用户项目的公开 URL 与 Anon Key 替换原配置；Cloudflare Pages 直接发布仓库根目录。

**Tech Stack:** HTML、CSS、原生 JavaScript、Service Worker、Supabase Auth/Postgres/RLS、Cloudflare Pages、Node.js 合约测试。

**Spec:** `docs/superpowers/specs/2026-08-16-cloudflare-supabase-migration-design.md`

## Global Constraints

- 不重新设计界面，不删除任何现有学习、账号、同步或共享功能。
- 学习状态必须先写入 `localStorage`，Supabase 不可用时仍可本地学习。
- 只把 Supabase Project URL 与 Publishable/Anon Key 写入前端；不得提交密码、Service Role Key 或访问令牌。
- Cloudflare Pages 无构建命令，发布目录为仓库根目录。
- 所有生产发布前必须通过静态资源、数据库合约、本地页面和生产页面验证。

### Task 2: 增加完整 Supabase 数据库初始化脚本

**Files:**
- Create: `tests/supabase-schema-contract.mjs`
- Create: `supabase/schema.sql`
- Modify: `README.md`

**Interfaces:**

- Produces: 可在 Supabase SQL Editor 一次执行的 `supabase/schema.sql`。

- [ ] **Step 1: 写失败的数据库合约测试**

```js
import assert from "node:assert/strict";
import { readFileSync } from "node:fs";

const sql = readFileSync(new URL("../supabase/schema.sql", import.meta.url), "utf8").toLowerCase();
for (const table of ["user_data", "note_shares", "feedback"]) {
  assert.match(sql, new RegExp(`create table if not exists\\s+public\\.${table}\\b`));
  assert.match(sql, new RegExp(`alter table public\\.${table} enable row level security`));
}
assert.match(sql, /unique\s*\(user_id,\s*note_id\)/);
assert.match(sql, /create or replace function public\.toggle_share_like/);
assert.match(sql, /auth\.uid\(\)/);
console.log("supabase schema contract passed");
```

- [ ] **Step 2: 运行测试并确认失败**

Run: `node tests/supabase-schema-contract.mjs`

Expected: FAIL，原因是 `supabase/schema.sql` 尚不存在。

- [ ] **Step 3: 编写数据库脚本**

`supabase/schema.sql` 必须包含以下真实对象：

```sql
create extension if not exists pgcrypto;

create table if not exists public.user_data (
  id text primary key,
  data jsonb not null,
  updated_at timestamptz not null default now()
);

create table if not exists public.note_shares (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  note_id text not null,
  word_key text not null,
  text text not null,
  likes uuid[] not null default '{}',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (user_id, note_id)
);

create table if not exists public.feedback (
  id bigint generated by default as identity primary key,
  user_id uuid not null references auth.users(id) on delete cascade,
  content text not null check (char_length(content) between 1 and 5000),
  created_at timestamptz not null default now()
);

alter table public.user_data enable row level security;
alter table public.note_shares enable row level security;
alter table public.feedback enable row level security;
```

脚本随后必须创建幂等策略：用户仅能管理自己的 `user_data`；认证用户可读共享妙计但只能增删改自己的妙计；用户只能写自己的反馈；`toggle_share_like(p_share_id uuid, p_user_id uuid)` 必须校验 `auth.uid() = p_user_id`，再以 SECURITY DEFINER 原子切换 `likes` 数组，并撤销 `public` 执行权限、只授予 `authenticated`。

- [ ] **Step 4: 运行数据库合约测试**

Run: `node tests/supabase-schema-contract.mjs`

Expected: `supabase schema contract passed`

- [ ] **Step 5: 更新部署说明**

在 `README.md` 的 Supabase 章节改为执行完整的 `supabase/schema.sql`，并明确该脚本同时建立同步、共享妙计、点赞和反馈所需对象。
